# HumanizeAI: research and architectural decisions
Research date: 14 October 2026. This report informed the MVP before application implementation. Product descriptions are vendor-reported capabilities, not independent performance assessments. No comparative benchmark was run.

## Competitive landscape

These products overlap and evolve. The comparison does not claim any competitor lacks safeguards, nor infer their proprietary architectures. Public documentation does not establish equivalent scientific accuracy across tools.

## Technical findings
1. **Style transfer.** [Jin et al.'s survey](https://arxiv.org/abs/2011.00416) frames style control and content preservation as distinct challenges. [Contextual style transfer](https://arxiv.org/abs/2005.00136) motivates surrounding-section context. For this MVP, separate analysis, rewrite and verification prompts make the transformation inspectable. This design is a hypothesis to evaluate, not a proven quality improvement.
2. **Meaning preservation.** Protect exact spans for equations, code, citations and numeric expressions; retain extracted factual propositions and qualifications in a semantic ledger. Exact token equality alone cannot prevent changing which group a number refers to. Independent semantic review must examine relationships, negation, causality, population and uncertainty.
3. **Similarity and inference.** [Sentence-BERT](https://arxiv.org/abs/1908.10084) supports efficient semantic embeddings. High similarity can coexist with a changed sign or negation. [Bidirectional entailment research](https://arxiv.org/abs/2111.07119) suggests checking both omission and unsupported addition. The MVP uses a structured LLM reviewer rather than a calibrated NLI classifier; its judgment is explicitly advisory. Future evaluations should compare small NLI models, embeddings and editorial labels.
4. **Author style.** Use samples to derive sentence length, formality, vocabulary and organization preferences. Samples should be treated as data, never instructions; avoid copying eight-word sequences absent from the source. A single short sample is not a reliable identity model. The MVP offers sample-conditioned rewriting and local descriptive diagnostics, without claiming a trained author model.
5. **RAG.** [Lewis et al.](https://arxiv.org/abs/2005.11401) describe retrieval-augmented generation for knowledge-intensive tasks. For academic use, retrieve metadata and available abstracts, attach immutable paper IDs, restrict generated evidence to supplied abstracts and record the evidence scope. Retrieval cannot compensate for missing or contradictory source evidence.
6. **Citation verification.** [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) supplies deposited scholarly metadata and DOI lookup without signup. Metadata can be incomplete or wrong; abstracts can have separate copyright restrictions. Resolving a DOI verifies a bibliographic record, not the truth of a cited claim. The application never uses a model to invent metadata.
7. **Scholarly APIs.** [Semantic Scholar's Graph API](https://api.semanticscholar.org/api-docs/graph) and [OpenAlex documentation](https://docs.openalex.org/) provide complementary records. API-key and quota requirements must be handled as runtime configuration. OpenAlex documentation redirected and could not be fully fetched during this research; current key eligibility therefore remains unverified here. Crossref is the default; other adapters surface failures rather than pretending results exist.
8. **Linguistic analysis.** Sentence length, repeated phrases and vague modifiers support actionable diagnostics. Readability formulas are sensitive to jargon and should not be academic-quality grades. spaCy and LanguageTool are candidates for deeper local diagnostics; scientific terminology needs discipline-specific allowlists.
9. **Detector limitations.** [Liang et al.](https://arxiv.org/abs/2304.02819) found false positives affecting non-native English writers and susceptibility to rewriting. These findings are tied to studied detectors and samples, not every detector. No authorship classifier, undetectability promise or detector score is included.
10. **Structured output.** [OpenAI's official guide](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat) distinguishes schema-constrained output from JSON mode. Schema adherence is not factual accuracy. The model adapter requests strict schemas and validates responses locally; incompatible providers fail explicitly.
11. **Editor stack.** [Tiptap tables](https://tiptap.dev/docs/editor/extensions/nodes/table) and [mathematics](https://tiptap.dev/docs/editor/extensions/nodes/mathematics) offer a path to a richer ProseMirror editor. [Conversion documentation](https://tiptap.dev/docs/conversion/content-types/structures-and-media/math-equations) documents equation import limitations. Document round-tripping requires dedicated fixtures.

## Architecture selected for this increment
The supplied stack is a starting suggestion. A dependency-free browser editor plus a JavaScript Worker was selected for a small, deployable MVP. It avoids a local LLM, multiple services and a database consuming laptop memory. Documents and source libraries persist in this browser, with JSON backup/restore and deletion controls. This is single-user persistence, not cloud synchronization or a production database. Secrets are never saved in project data.

A same-origin API proxies legitimate scholarly sources and calls configured OpenAI-compatible providers. Credentials can be server secrets; a user key is kept only in page memory. Provider endpoints are allowlisted HTTPS origins to prevent arbitrary network proxying. Manuscripts are sent only after the user checks an explicit model-consent control. Search queries go to the selected scholarly service and metadata is cached briefly; manuscript requests are not cached or logged. Errors expose safe status categories, never response bodies or credentials.

Pipeline: analyze a source passage into propositions/qualifications/technical terms → rewrite with protected-span tokens and surrounding context → restore exact spans → verify in both directions → deterministic checks → display diff and review notes. Unsafe revisions cannot be applied. No automatic evidence-generation prompt is used for original experiments. Sample-conditioned style remains an aid, not an authorship guarantee.

## Trade-offs and production migration
- Native contenteditable supports headings, emphasis and tables, and literal LaTeX; it is smaller than Next.js/Tiptap but does not offer rendered equation nodes or collaboration. Replace it with Tiptap after round-trip tests.
- Browser persistence is convenient for unpublished drafts but is not encrypted and can be lost if browser data is cleared. Export backups. Multi-user release requires authentication, per-project authorization and PostgreSQL migrations; do not simply place manuscripts in a shared cache.
- Hosted Worker execution fits HTTP integrations; FastAPI should be introduced for PDF/GROBID ingestion and background jobs. Use a separate process on demand rather than loading embedding models at boot on 8 GB machines.
- Use PostgreSQL with pgvector only after measured retrieval requirements justify it. Abstract search does not currently need a vector database.
- Retention controls apply to local drafts and in-memory keys. External providers have independent policies; consult and disclose them before use. A private Site access gate protects the hosted app; local development is loopback-only.
- For formal citations, migrate simplified APA/IEEE output to citeproc-js and CSL styles; import BibTeX with a mature parser. No full-text licensing assumptions.

## Differentiation and evaluation
Opportunity: a visible preservation ledger, blocked unsafe acceptance, explicit evidence scope and recoverable document history in one writing workspace. Whether this improves trust or editing speed is a testable hypothesis.

Evaluate numerical/citation/equation multiset preservation, unsupported-addition and omission detection against expert labels, and editor-rated precision and fluency. Include polarity changes, reassigned numbers, superscripts, confidence intervals, code, abbreviations, duplicate references and conflicting claims. Report false negatives as well as false positives. Unit tests verify contracts and failure paths; they do not establish model accuracy. No benchmark results are claimed.

## Delivery boundary
This increment targets the requested MVP and adds basic sample conditioning, local version history, diagnostics and source notes. PDF/DOCX ingestion/export, calibrated embedding/NLI validation, full CSL coverage, cloud storage, collaboration, cross-document reasoning and systematic-review-grade evidence synthesis remain future work. The README and interface identify these boundaries.
